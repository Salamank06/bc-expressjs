     1	# 🤖 Instrucciones para GitHub Copilot
     2	
     3	## 📋 Contexto del Bootcamp
     4	
     5	Este es un **Bootcamp de ExpressJS Zero to Hero** estructurado para llevar a
     6	desarrolladores con experiencia en JavaScript/TypeScript hasta el desarrollo de
     7	APIs REST profesionales, seguras y listas para producción con Node.js y Express.
     8	
     9	### 📊 Datos del Bootcamp
    10	
    11	- **Duración**: 16 semanas (~4 meses)
    12	- **Dedicación semanal**: 8 horas
    13	- **Total de horas**: ~128 horas
    14	- **Nivel de entrada**: Desarrollador con experiencia en JS/TS moderno
    15	- **Nivel de salida**: Desarrollador Backend Junior (Node.js / Express)
    16	- **Enfoque**: APIs REST modernas con Express, TypeScript, Prisma y PostgreSQL
    17	- **Stack**: Node.js 22+, Express 5, TypeScript 5.x, Prisma, PostgreSQL, Redis, Jest
    18

    21	## 🎯 Objetivos de Aprendizaje
    22	
    23	Al finalizar el bootcamp, los estudiantes serán capaces de:
    24	
    25	- ✅ Dominar el runtime de Node.js y el modelo de I/O no bloqueante
    26	- ✅ Construir servidores HTTP con Express 5 y TypeScript desde cero
    27	- ✅ Diseñar APIs REST siguiendo buenas prácticas (versioning, status codes, contratos)
    28	- ✅ Validar y sanitizar datos de entrada con Zod
    29	- ✅ Implementar persistencia con Prisma ORM + PostgreSQL y con Mongoose + MongoDB
    30	- ✅ Autenticar usuarios con bcrypt, JWT (access/refresh tokens) y cookies HttpOnly
    31	- ✅ Controlar acceso con RBAC (Role-Based Access Control)
    32	- ✅ Aplicar seguridad OWASP: Helmet, rate limiting, CORS, sanitización
    33	- ✅ Escribir tests unitarios e integration con Jest + Supertest
    34	- ✅ Gestionar archivos con Multer y almacenamiento en S3/Cloudinary
    35	- ✅ Implementar comunicación en tiempo real con Socket.io
    36	- ✅ Usar Redis para caché y gestión de sesiones
    37	- ✅ Documentar APIs con OpenAPI/Swagger
    38	- ✅ Dockerizar aplicaciones y desplegarlas con CI/CD en producción

    43	
    44	### Distribución por Fases
    45	
    46	#### **Fundamentos (Semanas 1-2)** — 16 horas
    47	
    48	- Runtime Node.js: event loop, módulos ESM, async/await, streams
    49	- TypeScript para backend: tsconfig, tipos, interfaces, generics
    50	- Express 5: servidor HTTP, routing, middleware chain, req/res lifecycle
    51	- Manejo de errores global y logging básico
    52	
    53	#### **Core API (Semanas 3-8)** — 48 horas
    54	
    55	- Arquitectura en capas: routes → controllers → services → repositories
    56	- Validación de schemas con Zod y manejo centralizado de errores
    57	- Base de datos relacional: PostgreSQL + Prisma ORM, migraciones, relaciones
    58	- Base de datos NoSQL: MongoDB + Mongoose, comparativa y casos de uso
    59	- Autenticación: bcrypt, JWT access/refresh tokens, cookies HttpOnly
    60	- Autorización & seguridad: RBAC, Helmet, rate limiting, CORS, sanitización
    61	
    62	#### **Avanzado (Semanas 9-13)** — 40 horas
    63	
    64	- Testing: Jest + Supertest, unit/integration, mocks, cobertura
    65	- File uploads & emails: Multer, S3/Cloudinary, Nodemailer
    66	- WebSockets: Socket.io, rooms, autenticación WS, patrones real-time
    67	- Caching & performance: Redis, paginación eficiente, compresión
    68	- Documentación: OpenAPI/Swagger, versionado, contratos de API
    69	
    70	#### **Producción (Semanas 14-16)** — 24 horas
    71	
    72	- Docker: Dockerfile multi-stage, docker-compose, secrets, variables de entorno
    73	- CI/CD: GitHub Actions, Railway/Render, monitoring con Logtail
    74	- Proyecto final integrador (semana 16)

   338	## 📝 Convenciones de Código
   339	
   340	### TypeScript Moderno
   341	
   342	```ts
   343	// ✅ BIEN - interfaces para tipos de dominio
   344	interface CreateUserDto {
   345	  email: string;
   346	  password: string;
   347	  name: string;
   348	}
   349	
   350	// ✅ BIEN - funciones async tipadas explícitamente
   351	export async function createUser(dto: CreateUserDto): Promise<User> {
   352	  const hashed = await bcrypt.hash(dto.password, 10);
   353	  return prisma.user.create({ data: { ...dto, password: hashed } });
   354	}
   355	
   356	// ✅ BIEN - manejo de errores tipado
   357	export class AppError extends Error {
   358	  constructor(
   359	    public statusCode: number,
   360	    message: string,
   361	  ) {
   362	    super(message);
   363	  }
   364	}
   365	
   366	// ❌ MAL - sin tipos
   367	export async function createUser(dto) {
   368	  return prisma.user.create({ data: dto });
   369	}
   370	```
   371	
   372	### Nomenclatura
   373	
   374	- **Clases y tipos**: PascalCase (`UserService`, `CreateUserDto`)
   375	- **Funciones y variables**: camelCase (`getUserById`, `accessToken`)
   376	- **Constantes globales**: UPPER_SNAKE_CASE (`JWT_SECRET`, `MAX_RETRIES`)
   377	- **Archivos de rutas**: kebab-case (`user.routes.ts`, `auth.routes.ts`)
   378	- **Archivos de servicios**: camelCase + sufijo (`user.service.ts`)
   379	- **Archivos de controladores**: camelCase + sufijo (`user.controller.ts`)
   380	- **Idioma**: inglés para código, español para documentación

   413	El bootcamp enseña testing con **Jest** y **Supertest**.

   415	### Estructura de Tests
   416	
   417	```ts
   418	// __tests__/user.service.test.ts
   419	import { UserService } from "../src/services/user.service";
   420	import { prismaMock } from "./mocks/prisma.mock";
   421	
   422	describe("UserService", () => {
   423	  it("crea un usuario con contraseña hasheada", async () => {
   424	    const dto = { email: "test@test.com", password: "123456", name: "Test" };
   425	    prismaMock.user.create.mockResolvedValue({ id: "1", ...dto });
   426	
   427	    const user = await UserService.create(dto);
   428	
   429	    expect(user.id).toBe("1");
   430	    expect(prismaMock.user.create).toHaveBeenCalledTimes(1);
   431	  });
   432	});
   433	```
   434	
   435	### Integration Tests con Supertest
   436	
   437	```ts
   438	// __tests__/auth.integration.test.ts
   439	import request from "supertest";
   440	import { app } from "../src/app";
   441	
   442	describe("POST /api/v1/auth/login", () => {
   443	  it("retorna 200 y token con credenciales válidas", async () => {
   444	    const res = await request(app)
   445	      .post("/api/v1/auth/login")
   446	      .send({ email: "test@test.com", password: "123456" });
   447	
   448	    expect(res.status).toBe(200);
   449	    expect(res.body).toHaveProperty("accessToken");
   450	  });
   451	
   452	  it("retorna 401 con credenciales inválidas", async () => {
   453	    const res = await request(app)
   454	      .post("/api/v1/auth/login")
   455	      .send({ email: "test@test.com", password: "wrong" });
   456	
   457	    expect(res.status).toBe(401);
   458	  });
   459	});
   460	```
